# Typhon workspace interop v1

Eclipse consumes Typhon's native `ext-workspace-v1` global through the shared
Wayland connection. There is no `hyprctl`, `astreactl`, shell subprocess,
polling loop, or compositor-specific fallback in this path.

## Official protocol binding

The client binding is generated by `wayland-scanner` from
`shared/platform/typhon/protocols/ext-workspace-v1.xml`. That file is the
unchanged official staging definition from the locked `wayland-protocols`
0.32.12 source (`SHA-256 2437063d2011a06419380ab97acb84fe424a9747f004205b298fd407ace1a6dd`).
The generated client header and private C implementation are build outputs and
are not hand-maintained.

## State model

`TyphonWorkspaceClient` is a consumer of the existing
`TyphonSharedConnection`. It binds `ext_workspace_manager_v1` when a generation
becomes ready, listens to the single group and its workspace handles, and
buffers all handle properties in `TyphonWorkspaceState`.

The reducer uses the protocol ID as identity. Names are display data, so a
name update cannot replace or reorder a workspace. State is published to
`WorkspaceModel` only after `manager.done`; partial initial events and partial
updates never reach QML. The model keeps the numeric protocol name for display
and the stable `typhon.workspace.N` ID for actions.

Only workspaces whose protocol capabilities include `activate` are actionable.
The native action is exactly:

```cpp
ext_workspace_handle_v1_activate(handle);
ext_workspace_manager_v1_commit(manager);
```

The model and QML do not optimistically change `active`. The next committed
server snapshot is authoritative.

## Reconnect and lifecycle safety

The client tracks the shared connection generation. A disconnect clears the
published snapshot and action availability. A stale generation cannot commit
state or publish a snapshot. On a new generation, old protocol proxies are
destroyed before the registry is rebound, and manager `finished` is treated as
the end of that generation.

`ShellRuntime` owns the client and controller, starts them after the shared
connection, maps committed records into the existing `WorkspaceModel`, and
stops the workspace client before stopping the shared transport.

## UI routing and tests

`BarController.workspaceController` exposes the native controller to
`LauncherSurface`. `WorkspaceStrip` disables hover/click affordances when
activation is unavailable and routes a click using the stable protocol ID.
The QML smoke test exercises the real hit target through a fake native
controller and verifies that `typhon.workspace.2` reaches the action boundary.
Reducer tests cover manager-done buffering and stable-ID identity.

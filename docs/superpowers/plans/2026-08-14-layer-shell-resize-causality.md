# Typhon + Eclipse Layer-Shell Resize Causality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve correct layer-shell configure/ack causality for client-driven resizes and remove Eclipse's deliberate frame-by-frame top-level Dock width animation.

**Architecture:** Typhon will carry an explicit arrangement cause through the layer-surface commit path and record configure provenance in each pending configure. A configure generated for the surface whose client commit is currently being processed will not retroactively reject that same buffer commit, while initial and compositor-driven configure validation remain strict. Eclipse will keep dynamic Dock membership and change only the physical top-level width contract from animated to atomic structural updates.

**Tech Stack:** Rust, Smithay/Wayland server protocol, Cargo tests, Qt 6/QML, CMake/CTest, QML lint.

## Global Constraints

- Use protocol-level evidence before changing production code.
- Write and observe a failing Typhon regression before the production fix.
- Preserve initial configure/ack, stale configure, old-buffer, unmap/remap, and exact configure snapshot semantics.
- Represent configure causality explicitly; do not infer it from serial order, buffer size, timing, or namespace.
- Do not add Eclipse-specific or compositor-specific hacks, timers, sleeps, or protocol-error suppression.
- Keep all Markdown/documentation in English.
- Preserve Eclipse dynamic rows, activation, runtime authority, anchoring, exclusive zone, styling, and visual item animations.
